# Buyer Insights Hub

Create a new project called HC4M Buyer Insights based on the uploaded spreadsheet.

The goal is to turn the spreadsheet into a clean, professional web dashboard that makes LeadProsper buyer activity easy to understand for users who do not work inside LeadProsper every day.

Project purpose

This dashboard is for Home Cash 4 Me (HC4M) and should eventually connect to our LeadProsper data so that the spreadsheet can be replaced by live reporting.

For this first prototype, use the uploaded spreadsheet as the source of truth.

The spreadsheet contains all HC4M leads for August 1, 2026, along with the outcome of each lead for every connected buyer.

Each buyer has its own tab showing:

Lead date/time

Lead ID

Buyer Status

Last Stage

Buyer Ping Response

Buyer Bid

Whether the lead was sent to that buyer

Buyer Purchase Price

Outcome Detail

HTTP Status

The Lead ID is also linked directly to the corresponding LeadProsper lead detail page.

Important buyer-status logic

The dashboard needs to make buyer-level results very clear.

Accepted should only mean that the specific buyer accepted or purchased that specific lead.

Do not use the overall LeadProsper lead status as the buyer’s status.

Use buyer statuses such as:

Accepted

Outbid

Rejected

Filtered Out

Not Accepted

These statuses should be visually distinct and easy to scan.

For example:

Accepted = this buyer actually purchased the lead

Outbid = this buyer qualified or bid, but another buyer won

Rejected = this buyer declined the lead

Filtered Out = LeadProsper rules prevented the buyer from receiving or being pinged on the lead

Not Accepted = the buyer progressed through part of the process but did not ultimately receive or accept the lead

Design direction

The dashboard should feel like a modern business intelligence application, not like a spreadsheet.

Use:

Clean cards

Clear typography

Responsive layout

Tables with sticky headers

Search and filters

Status badges

Tooltips where useful

Charts that can be understood quickly

Desktop-first layout that also works well on tablets

Keep the interface simple enough that an executive or account manager can understand the results without needing to know LeadProsper terminology.

Avoid exposing technical API details unless they are useful.

HTTP Status should remain available in the detailed view, but it does not need to be prominent on the main dashboard.

Color and status treatment

Use consistent visual status indicators throughout the application.

Suggested treatment:

Accepted — positive/success

Outbid — neutral or informational

Rejected — negative

Filtered Out — warning

Not Accepted — muted

Do not rely only on color; always display the written status as well.

Future LeadProsper integration

For this prototype, use the uploaded spreadsheet.

However, build the application structure so the spreadsheet can later be replaced by live LeadProsper API data without redesigning the frontend.

The future data model should support:

Lead

Lead ID

Lead Date

Campaign

Overall campaign-level operational information

Buyer Attempt

Lead ID

Buyer

Buyer Status

Last Stage

Ping Response

Bid

Post Sent

Purchase Price

Outcome Detail

HTTP Status

A single lead can have many Buyer Attempts.

Do not structure the database as if each lead belongs to only one buyer.

Important privacy requirement

Do not display or create fields for personally identifiable seller information.

The dashboard should focus on operational lead and buyer-response information such as Lead ID, buyer, statuses, bids, purchase prices, dates, and sanitized outcome details.
